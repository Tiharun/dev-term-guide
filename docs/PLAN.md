# 기획 결정사항

용어 정의는 [GLOSSARY.md](../GLOSSARY.md) 참고.

## 목적
- 공부용 사전 + Claude 지시용. 용어 카드마다 말하기 예문.
- 증상 색인으로 용어를 몰라도 찾기.

## 범위
- 카테고리 13개: 개발 기본, 웹사이트, 디자인·UI/UX, 프론트엔드, 백엔드, 데이터베이스, 서버, Git·협업, 배포·DevOps, 보안, 성능·최적화, 버그·디버깅 현상, AI·Claude와 일하기
- 추가 카테고리(2026-10-31 결정): 터미널·명령줄(개발 기본 다음), 네트워크(서버 다음), 모바일 앱(프론트엔드 다음), 테스트(버그 다음), 기획·문서(AI 앞)
  - 추가 하위항목: 터미널=자주 쓰는 명령어, 기획·문서=문서 종류, 모바일 앱=앱 스토어·출시, 테스트=테스트 종류, 네트워크=프로토콜·포트
  - 기획·문서의 "모션용어 및 연출"은 화면 흐름 기획 용어로 채운다
- 기존 하위항목도 보강하고, 개수 규칙 때문에 흩어진 용어는 정리한다
- 새 디자인 하위항목에 더 맞는 기존 카드는 옮긴다(예: Checkbox·Input Field→폼·입력, Modal·Toast→상태·피드백, Breadcrumb·Pagination→내비게이션). 다른 카테고리로 옮겨도 즐겨찾기·외운 체크는 이어지게 한다
- 같은 용어는 카드 하나만 만들고 다른 곳은 관련 용어로 연결(기존 중복 Component·Dark Mode는 유지)
- 제작 순서: ① 디자인 화면 하위항목 + 디자인 카테고리 전체 보강(완료 2026-10-31) → ② 새 카테고리(터미널·명령줄 완료 2026-11-01, 네트워크 완료 2026-11-01, 테스트 완료 2026-11-01, 모바일 앱 완료 2026-11-01, 기획·문서 완료 2026-11-02, ② 끝 · 다음은 ③) → ③ 나머지 카테고리 보강(+그림 재제작, 카테고리별. 개발 기본 완료 2026-11-02, 웹사이트 완료 2026-11-02, 프론트엔드 완료 2026-11-03, 백엔드 완료 2026-11-03, 데이터베이스 완료 2026-11-03, 서버 완료 2026-11-04, Git 완료 2026-11-06, 다음은 배포). 단계마다 브라우저 확인
- ① 상세 설계: [docs/superpowers/specs/2026-10-31-design-screen-terms-design.md](superpowers/specs/2026-10-31-design-screen-terms-design.md)
- 데모 조작: 폼·제스처·상태처럼 직접 해 봐야 아는 카드만 클릭·드래그·입력 가능(마우스·터치·키보드). 그림 스타일은 실제 화면 모형 기본 + 이름이 비유인 용어만 비유 일러스트
- 저장소: git(2026-10-31 시작). 작업 단위마다 커밋
- 디자인 하위 그룹: 웹디자인 / 앱·프로그램 UI / 디자인 툴(Figma) / 폰트·타이포그래피
- 디자인 추가 하위항목(2026-10-31 결정): 폼·입력, 상태·피드백, 내비게이션, 표·목록, 시각 스타일, 제스처·조작, 기기 화면, 이미지·미디어
- 공통 하위항목: 기본, 필수, 모션용어 및 연출, 심화, 추천 개념 + 카테고리별 추가 하위항목(목록은 제작 전 확인)
- 하위항목당 용어 개수 제한 없음(기존 8~12개 규칙은 2026-10-31 폐지). 현업에서 통하는 용어를 가능한 한 많이 넣는다
- 새 용어를 넣을 때 증상 색인도 함께 추가

## 용어 카드
- 영문명·한글명 / 한 줄 정의 / 데모·도식 / 말하기 예문 / 관련 용어 / 난이도
- 코드 조각은 심화에만
- 실무에서 통하는 용어 우선. 공식 출처(MDN, web.dev 등)는 확인된 경우만 링크
- 근거 표시: "공식" / "실무"
- 현업 은어(누끼, 컨펌 등) 포함, "현업 은어" 표시 + 정식 용어 병기
- 말하기 예문은 정식 용어로, Claude·사람 모두에게 통하게

## 유지보수
- 사이트 이름·용어 데이터는 HTML 안 한 곳에 모아 쉽게 추가·수정
- 제목 글꼴(Hahmlet)은 지금 파일에 쓰인 글자만 내장한 서브셋. 새 용어에 처음 쓰는 한글이 생기면 그 글자만 대체 글꼴(바탕)로 보이므로, 용어를 많이 추가한 뒤에는 서브셋을 다시 만들어 `/* FONT:START */`~`/* FONT:END */` 사이를 교체

## 표현
- 사진 대신 데모(실제 동작) + SVG 도식, 오프라인 동작 단일 HTML
- 모션: 다시 재생, 나쁜 예/좋은 예 비교
- 모든 용어 카드에 데모·도식 필수. 파일 크기보다 품질 우선(2026-10-31). 용어를 가장 잘 보여주는 모션을 다양하게, 모션이 필요 없으면 흐름이 보이는 그림으로
- 기존 카드 중 용량 때문에 간단히 만든 그림도 다시 제대로 만든다: 글자 상자형(flow 140·big 42·stack 42개)은 새로 만들고, code·tbl·tree·git·http 등은 형식 유지하고 품질만 점검
- 그림 기준은 "초보자가 한눈에 이해하는가". 실제 사진 대신 직접 그린 SVG 일러스트·화면 모형
- 화면에 보이는 카드의 데모만 실행
